# Receipt-Backed Hermes Demo

Run this in a disposable repo. The commands below keep task receipts inside the demo folder by setting `ATRIS_TASKS_DB`.

1. Initialize the sample repo.

```bash
mkdir -p /tmp/hermes-atris-demo
cd /tmp/hermes-atris-demo
printf '# Hermes Atris Demo\n' > README.md
npx -y atris init
export ATRIS_TASKS_DB="$PWD/.atris/tasks.db"
```

expect: `atris init` prints created files such as `atris/ folder`, `MAP.md placeholder`, `TODO.md placeholder`, `logs/YYYY/ folder`, wiki scaffold, skills, and `Atris initialized`. It may ask one context question after scaffolding.

2. Load the workspace context.

```bash
atris activate
```

expect: a context card headed `Atris Activate - Context Loaded`, a ready state, core files including `atris/MAP.md`, `atris/TODO.md`, `atris/logs/YYYY/YYYY-MM-DD.md`, and wiki health.

3. Create a bounded task.

```bash
atris task new "Add README proof line so Hermes reviewers can verify the demo"
```

expect: the CLI prints a display id and title, for example `ABC-1 Add README proof line so Hermes reviewers can verify the demo`. Some versions also print a title-quality warning if the title does not explain enough.

4. Capture the task id from the open queue.

```bash
atris task list --status open
TASK_ID=$(atris task list --status open | awk '/^open[[:space:]]/ {print $2; exit}')
printf '%s\n' "$TASK_ID"
```

expect: `task list` prints a row like `open     ABC-1 Add README proof line...`, then the shell prints the id.

5. Claim the task as the Hermes operator.

```bash
atris task claim "$TASK_ID" --as hermes-agent
```

expect: `claimed ABC-1 as hermes-agent`.

6. Make a small edit and run the proof command.

```bash
printf '\nDemo proof line.\n' >> README.md
grep -q "Demo proof line" README.md && printf 'grep exit 0\n'
```

expect: `grep exit 0`. The command is silent unless the line exists.

7. Move the task to review with proof.

```bash
atris task ready "$TASK_ID" --proof '[verified] `grep -q "Demo proof line" README.md` passed (exit 0); README.md contains the demo line.'
```

expect: the CLI may advise adding `--landing`, then prints `ready for approval ABC-1 v<N>`, `Result trace recorded.`, and `Proof is ready; one more agent check before human approval.`

8. Inspect the task receipt.

```bash
atris task show "$TASK_ID"
```

expect: `READY FOR APPROVAL ABC-1`, a result summary, `Details: [verified]`, `Landing: waiting on human`, and a review command such as `atris task review-chat ABC-1 --as codex-review`.

9. End with a plain-English recap.

```bash
atris recap
```

expect: `RECAP`, a `NEEDS YOU` section for the review item, a checked count, and a note that `atris recap --share` can produce a shareable summary.

## Receipts On Disk

- `atris/MAP.md`: navigation file the next agent reads before searching.
- `atris/TODO.md`: rendered task view scaffolded by init.
- `.atris/state/tasks.projection.json`: current task projection generated by `atris task`.
- `.atris/tasks.db`: task ledger for this demo because `ATRIS_TASKS_DB` points there.
- `atris/logs/YYYY/YYYY-MM-DD.md`: daily journal created by init or activate.
- `atris/wiki/STATUS.md`: wiki health read by `atris activate`.

The proof is not a claim in chat. It is stored in the task ledger, appears through `atris task show "$TASK_ID"`, and is summarized by `atris recap`.
