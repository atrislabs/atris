# Note shape

How one note should look. Back to [SKILL.md](SKILL.md).

## Rules

- One idea per note. If you need two headings that could each stand alone, it is two notes.
- Under about 80 lines. Long logs, transcripts and code go one hop deeper in `atris/context/` or a linked file.
- First line under the title says what the note covers and links back to its index.
- Rules come first and the real examples that prove them follow. Put each example right under the rule it backs, never in a separate examples file.
- Say where the knowledge came from: a source path, a date or the person who decided it.
- Name code by path and the function name beside it. That way a moved line can be found again.

## Example

Taste files are the model. `atris/taste/TASTE.md` is one screen of rules. Each line links to a note like `copy.md` that holds the reason and the real picks that won or lost. `atris/skills/taste/notes.md` spells out the shape.
