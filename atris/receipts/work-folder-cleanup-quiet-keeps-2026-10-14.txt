Worktree cleanup counts healthy keeps on one line and names the rest

Files edited: commands/worktree.js, test/worktree-removal-guard.test.js, test/member-tidy.test.js, atris/team/architect/logs/2026-10-14.md, this receipt.

What changed: kept folders that need no one (work still in progress, in use by a running process, the main and current checkouts, protected branches, fresh copies) now share one count line. Folders that need a person (uncommitted work, pins, refusals, git holds, unreadable folders) keep their own named line. Any keep reason not on the healthy list prints by name, so a new reason can never be hidden. The JSON output still lists every kept folder.
