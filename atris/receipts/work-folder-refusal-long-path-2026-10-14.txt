Refusal reasons keep git's words when the folder path is long

Files edited: commands/worktree.js, test/worktree-removal-guard.test.js, atris/refs/MAP-NOTES.md, atris/team/architect/logs/2026-10-14.md, this receipt.

What changed: the shared line that explains why git refused to remove a folder (printed by tidy, reap, worktree cleanup, autopilot, land and fleet review) used to cut git's message at 160 characters. Long temp folder paths ate the limit, so the words that say what went wrong were lost. Every report already prints the folder beside the reason, so git's copy of the path now shrinks to the folder's name. A line that is still too long keeps its start and its end.
