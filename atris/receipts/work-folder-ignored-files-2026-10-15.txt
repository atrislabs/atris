Finished copies lose ignored files on cleanup, 2026-10-15

Finding: cleanup removes a finished, merged copy with a plain git folder
removal. Git treats ignored files as disposable, and the status check cleanup
relies on does not list them, so the copy looks clean and its ignored files
are deleted without a word in the preview or the apply output.

Reproduction (throwaway fixture under /tmp, cleanup run in a guarded subshell
whose folder was checked first):
- fixture ignores .env.local and notes/
- finished copy done-copy holds .env.local (a token line) and notes/plan.md
- copy aged past the fresh-copy grace

Risk of the obvious fix: keeping every copy with any ignored file would stop
cleanup for 108 of 117 copies, so the rule needs a measured list of
throwaway places, and the preview should name what kept a copy.
