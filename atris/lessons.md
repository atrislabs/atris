- **[2026-06-16] string-metric-is-pre-filter-not-verifier** — pass — Tested whether a deterministic string metric can verify PROMPT quality (atris/experiments/kernel-prompt-discipline): it cannot, and the ceiling is reproducible. measure.py scores a prompt 0..1 on spine-marker coverage + discipline + a substance gate; keep/revert works for HONEST regressions (full v1 kernel 0.28, gut-the-spine reverts at 0.086, compressed spine kernel kept at 1.0) — a good CI pre-filter that catches bloat and spine-gutting. But two independent adversarial reviewers (judge≠worker, spawned as subagents) broke it three ways to 1.0, and after whole-token + diversity-gate fixes the deep holes remain BY CONSTRUCTION: a coherent anti-prompt that name-checks every marker while instructing the opposite still scores 1.0 (/tmp/ceiling_antiprompt.txt: coverage 1.0, distinct 140), and a genuinely-good kernel written in synonyms scores 0.0 (/tmp/ceiling_synonym.txt: coverage 0, distinct 207). - **[2026-06-16] self-report-honesty-bugs** — pass — A 3x adversarial review of `atris pulse` (the self-improvement heartbeat) found three bugs, all of which made the system LIE ABOUT ITSELF — the worst class for an honesty/liveness substrate. (1) Permanent-stale: `detectStaleTick` flagged stale if ANY historical tick ever crashed, so one crash made a fully-recovered loop read dead forever; fix = liveness reflects the LATEST receipt only, `findOrphanStarts` still surfaces old crashes in the feed but not as fatal. (2) Reward inflation: reward keyed off `git status --porcelain` (the whole dirty tree) plus `actorReason==='completed'`, so every tick re-credited pre-existing dirt (reward 11 from ~2 real changes); fix = `scoreTick({verifyPassed, producedWork})` where producedWork is the tick's actual delta from a before/after `gitSnapshot` (new commit OR newly-dirtied files), never the standing tree. (3) Liveness/lock timeout conflation: one `STALE_TICK_MS=30m` was used for both lock-steal (a tick is hung) and liveness (loop stopped firing); after cadence went hourly the heartbeat flapped "stale" for half of every hour; fix = separate `LIVENESS_STALE_MS=150m` (>2 cadences) from the 30m lock-steal. Rule: when a system reports on its own health/reward, adversarially attack those self-reports first — a heartbeat that needs an app open is not a heartbeat, and a reward that counts the standing dirty tree is not a reward. Each fix is detector-backed (recovery test, no-inflation test, no-flap test). Bug #3 was caught by reviewing LIVE data, not just code — the restart that showed a false "stale" exposed it.
