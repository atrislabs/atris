# lessons.md — What We Learned

> Append-only. One line per lesson. Harvested by validator after every feature.

---

- **[2026-02-09] validate-md-gap** — pass — The validate.md template existed but nothing in the system told agents to use it. Three places needed updating: README, CLI output, workflow docs. Always check that templates are wired into the actual workflow, not just sitting in _templates/.
- **[2026-02-09] wire-the-loop** — pass — Same pattern one level up: specs said the right things but CLI commands didn't pass the info through. When you add a new artifact (like lessons.md), grep every command that surfaces context files and add it there too. The wiring layer is always the gap.
- **[2026-02-10] map-line-drift** — fail — MAP.md line references drift silently when functions grow. Start lines drift by 2-4 (minor), but end lines drift by 30-200 (major) because new features get appended inside existing functions. After any feature that adds code to workflow.js, init.js, or brainstorm.js, re-verify the MAP.md end-line for that function.
- **[2026-02-10] auth-duplication** — Auth logic exists in two places: `utils/auth.js` (canonical) and `bin/atris.js:1501-1812` (inline copy). The inline copy lacks `chmod 0o600` on credential save and has no HTTP timeout. Changing auth behavior means patching both unless you refactor to a single source.
- **[2026-02-10] unguarded-token-usage** — `commands/workflow.js`, `commands/brainstorm.js`, `commands/integrations.js`, and `bin/atris.js` (agent/chat) all call `loadCredentials()` and use the raw token without `ensureValidCredentials()`. Only `log-sync.js` and `auth.js` use the full refresh guard. Expired tokens silently fail in agent mode, workflow --execute, and integrations.
- **[2026-02-10] oauth-is-code-exchange-not-redirect** — The CLI OAuth flow opens `{APP_URL}/auth/cli` in browser, user gets a one-time code (5-min expiry), pastes it in terminal, CLI exchanges via `POST /auth/cli/exchange`. No local HTTP server needed. This is simpler but requires user to copy/paste.
- **[2026-02-14] backend-first-then-skill** — When adding new CLI capabilities, check the backend first (`atrisos-backend/backend/routers/integrations/`). Gmail drafts, calendar, drive all already had full backend support — we just needed to write the SKILL.md to expose them. Don't build backend unless it's actually missing.
- **[2026-02-14] dead-code-in-auth-flow** — Backend `auth.py:635` has a CLI-specific code path (`normalized_path == "/auth/cli"`) that never fires because the frontend login route wraps `next` into `/auth/callback?next=...`. The flow still works — it just takes an extra redirect through the general exchange path. Not broken, but dead code.
- **[2026-03-09] heal-needs-strict-only** — The old `findSymbolLine` had a loose fallback (`\bsymbol\b` anywhere on a line) that could heal MAP.md refs to wrong locations — e.g., a comment mentioning the symbol instead of its definition. Strict-only patterns (function/const/class/def declarations) are safer. False negative (unhealable) beats false positive (healed to wrong line).
- **[2026-04-06] map-context-needs-identifiers** — MAP.md refs with descriptive context like "(main routing logic)" or "(prints table)" can't be auto-healed because the healer searches for identifiers. Use actual symbol names: "(knownCommands dispatch)", "(cycleTimings forEach)". The healer verifies these, descriptions it can't.
- **[2026-04-06] schema-over-infrastructure** — The Karpathy knowledge wiki pattern doesn't need new services or endpoints. Adding a `last_compiled` + `sources` frontmatter contract to atris.md makes existing agents into knowledge compilers. The schema tells the LLM what to do — no plumbing needed.
- **[2026-04-06] suggestion-engine-needs-skip-keys** — When autopilot suggests tasks in dry-run or skip mode, each suggestion kind needs a unique skip key (e.g., 'fix-map-refs', 'incomplete-features', 'review'). Without this, the same suggestion repeats every iteration.
- **[2026-04-06] features-outlive-status** — Feature idea.md files say "planning" long after the feature ships. The autopilot suggestion engine found this: brainstorm, cli-ux-simplification, and team-member-standard were all "planning" but fully implemented. Validate.md creation is the right trigger to update status.
- **[2026-04-08] benchmark-prompt-paths** — fail — Endstate dry-run receipt tests can pass while real benchmark prompts are malformed, because `runTaskOnce()` never executes in dry-run. For benchmark harness changes, add one direct prompt assertion alongside receipt tests so the live path is covered before closeout.
- **[2026-04-08] clean-absolute-source-paths** — fail — `commands/clean.js` used `path.join(cwd, source)` to resolve wiki source paths, silently mangling absolute paths into `<cwd>/<abs-path>` and reporting every absolute-path source as "missing". The wiki convention is absolute paths in frontmatter (per ingest task notes C7/C18/C22). Always guard with `path.isAbsolute(p) ? p : path.join(base, p)` when a config field accepts either form.
- **[2026-04-08] no-authed-route-group** — pass — atrisos-web has no `app/(authed)` route group; the protected surface is a flat allowlist in `middleware.ts:5-13` (dashboard/account/profile/settings/billing/payment). Task descriptions referencing `app/(authed)` are wrong — verify route group assumptions against middleware.ts before writing wiki tasks for Next.js projects.
- **[2026-04-08] inbox-trigger-survives-shipping** — pass — Endgame `wiki-for-atrisos-web` shipped end-to-end (T1–T4e, C15–C55) but inbox item I1 stayed in `## Inbox`, so autopilot kept re-spawning "Break down inbox idea" validator ticks. When the breakdown of an inbox idea is shipped, move the inbox item to `## Completed` in the same closeout — otherwise the trigger keeps firing redundant ticks.
- **[2026-04-08] inbox-parser-eats-hr-separator** — fail — `commands/autopilot.js:116`, `commands/run.js:157`, and `commands/workflow.js:81` all filtered inbox bullets with `l.trim().startsWith('-')`, which silently treats the trailing `---` markdown horizontal-rule separator as a bullet; `.replace(/^-\s*/, '')` then strips one dash and yields `--`, so an empty inbox spawns a "Break down inbox idea: '--'" tick on every autopilot run. Fix: require `- ` (dash + space) and ≥1 trailing char in any inbox-bullet filter — never trust bare `startsWith('-')` against markdown that contains `---` separators.
- **[2026-04-08] inbox-parser-fix-shipped** — pass — Patched `commands/autopilot.js:116` to the same `- ` + length>2 filter already used by run.js and workflow.js; `atris autopilot --dry-run` now emits zero inbox-kind suggestions, proving the loop's own validator-written lesson round-tripped into a shipped code change.
