## Feature: Missions (`atris mission`)

**Purpose:** Durable objective loop with owner, verifier command, receipt, member now file, and status surface.

- **Entry point:** `bin/atris.js` dispatch for `mission`
- **Handler:** `commands/mission.js`; cloud enqueue/status HTTP client: `lib/cloud-mission.js`
- **Core flows:** `start` creates `.atris/state/missions.jsonl`; `status` renders `atris/status/now.md`; `run --cloud` enqueues `/atris2/missions` without entering local tick machinery and `status --cloud <task_id> [--watch]` reads it back; `goal` writes `.atris/state/codex_goal.json`; `goal-loop` runs the bounded overnight controller; `tick --verify` runs the configured verifier, while `tick --verify "<cmd>"` writes a one-off passing/failing verifier receipt without mutating mission config; `run --due` selects one runnable (`planning`/`running`/`ready`) verifier mission for heartbeats and skips paused/blocked work; `run` executes bounded Claude ticks behind a mission lock; `watch` is a read-only live heartbeat that prints a line per tick as it lands (`watchMission()` in `commands/mission.js`; returns a never-resolving promise so the bin router doesn't exit it); `complete`/`stop` close the mission. Cloud regression: `test/cloud-mission.test.js`.
- **Run phases:** `runMission()` threads one context through `parseAndValidateMissionRunPhase()`, `resolveMissionRunPhase()`, `executeMissionRunTicksPhase()`, `verifyMissionRunTickPhase()`, and `completeMissionRunPhase()`; phase functions stay file-local.
- **Mission report:** `mission report [id]` shows the operator outcome, worker summary, proof receipts, next move, and a compact chronological timeline from recent tick receipts; full-budget continuation language appears only after a useful worker receipt exists, so an untouched mission reports that it is waiting for its first check-in. Regression: `test/mission-status.test.js`
- **Liveness surface:** `status` text output includes `missionHeartbeatLines()`; ordinary missions show `last tick`, budget task work shows `last mission receipt`, and `mission status --help|-h|help` opens read-only usage instead of resolving a mission named help. Paused missions print `paused: <reason>` and never show remaining-time commitment language. Regression: `test/mission-heartbeat.test.js`, `test/mission-status.test.js`
- **Native-goal help safety:** `mission goal --help|-h|help` and `mission goal-loop --help|-h|help` return read-only usage before refreshing goal state or starting due work. Regression: `test/mission-status.test.js` (`mission help documents status filters`)
- **Dead mission lock recovery:** `acquireMissionLock()` probes the recorded PID and reaps an orphan lock before retrying acquisition; live PID locks still return the normal busy error. Regression: `test/mission-status.test.js` (`mission lock reaps a dead owner before acquiring`).
- The allowed-rate-limit timed-run fixture proves future allowed-window metadata never becomes a cooldown pause, while an independent repeated-summary breaker still stops the flat run. Regression: `test/commands-1.test.js` (`allowed rate-limit info with a future resetsAt does not pause a timed run`).
- **Runners & models:** `mission start --runner manual|claude|atris2|codex_goal [--model <id>]`. `claude` spawns the configured local runner binary (`ATRIS_RUNNER_BIN`, legacy `ATRIS_CLAUDE_BIN`, default `claude`) per tick via `spawnClaudeTick()`; model resolves from `mission.model` -> `ATRIS_RUNNER_MODEL` -> `ATRIS_RUNNER_PROFILE` -> legacy `ATRIS_CLAUDE_MODEL` -> `opus` in `lib/runner-command.js`; shell worker paths (`autopilot`/`run`/horizon checks) use the same shared runner command and expose per-run `--runner-profile`, `--runner-bin`, `--runner-template`, and `--runner-model` flags for runner swaps/model changes. Profile roster: `atris-fast`, `claude`, `codex`, `cursor`, `devin`, `hermes` (alias `hermes-agent`). Bad profile/bin availability errors are formatted by `runnerAvailabilityFailureMessage()` so overnight receipts name the config fix instead of rethrowing while reporting failure. Product-ladder example: `ATRIS_RUNNER_PROFILE=atris-fast atris run --once` literally launches `ax --fast` with model metadata `atris:fast`; later `atris:3`/`atris:4` can move behind that profile. Raw-engine example: `ATRIS_RUNNER_BIN=glm-runner ATRIS_RUNNER_MODEL=glm-5.2 ATRIS_RUNNER_COMMAND_TEMPLATE='{bin} --model {model} --prompt-file {promptFile} {allowedToolsFlag}' atris run --once`. `atris2` runs each tick as one `/atris2/turn` on the AtrisOS backend via `runAtris2Turn()` (exported from `commands/probe.js`; default model `atris:fast`, stateless per tick - continuity lives on disk; no creds -> mission pauses `auth-required`; receipt carries `result.atris2` with engine/tools_run/receipt_text). `codex_goal` publishes the goal for a live Codex session to pull. Regression: `test/mission-atris2-runner.test.js`, `test/mission-model-resolution.test.js`, `test/runner-command.test.js`, `test/autopilot-runner-model.test.js`
- **Codex dispatch watchdog:** `scripts/det/codex-watchdog.js:65` runs commands with null stdin, live byte forwarding, one silent-start retry, process-group kills, and a total runtime cap; `test/codex-watchdog.test.js:36` covers exit and output passthrough, double-stall failure, and first-stall recovery.
- **Worktree evidence:** receipts include capped git dirty counts/samples; `mission start` captures a write-once baseline sidecar (`.atris/state/mission-baselines/<id>.json`, `captureMissionWorktreeBaseline()` in `commands/mission.js`) and `worktreeReceipt()` subtracts those paths so `unverified_dirty` flags only `new_since_baseline` dirt, not pre-existing workspace noise (legacy missions without a sidecar fall back to `baseline_source: tick_start`).
- **Baseline lifecycle:** closing a mission (`complete`/`stop`, not `pause`) prunes the sidecar via `pruneMissionWorktreeBaseline()` and folds a `{captured_at, dirty_count, dirty_hash, path_count}` audit summary into `mission.worktree_baseline`; paused missions keep theirs so resume ticks still subtract it. Regression: `test/mission-baseline-lifecycle.test.js`
- **Loop exhaust filter:** `new_since_baseline` excludes paths under `.atris/`, `atris/runs/`, `atris/status/` (`isLoopExhaustPath()`) so multi-tick missions never flag their own receipts/state/status writes as unverified dirt; raw `new_dirty_*` fields stay unfiltered.
- **No-progress backstop:** `buildTickPrompt()` sends an idle worker through the first fueled repo backstop (tests, feature proof, TODO backlog, then proved debloat), requires real-surface proof, self-lands safe lanes, and records ladder-sourced landings as SHIPPED judge cards; `mission run` still stops after two structurally idle ticks and appends a decision card through `appendMissionJudgmentCard()`. Regression: `test/mission-idle-stop.test.js`.
- **Run receipt pruning:** `atris mission prune-runs [--apply] [--days <n>] [--keep-newest <n>] [--json]` (`pruneRuns()`/`runsPruneLines()` in `lib/runs-prune.js`, routed by `commands/mission.js`) keeps recent/newest/referenced `atris/runs` files, writes a compact `_archive/prune-*.json` manifest on apply, then deletes only old unreferenced clutter. Regression: `test/mission-status.test.js`
- **Ledger self-compaction:** every `saveMission()` calls `compactMissionLedger()` (`lib/mission-ledger-compact.js`); once `.atris/state/missions.jsonl` history outweighs live missions 4:1 (and the file passes a cheap size gate) it atomically rewrites to one row per mission: latest state, first assigned display number, first-seen order, exactly what `loadMissionMap()` reconstructs. Regression: `test/mission-ledger-compact.test.js`
- **Isolated missions:** `mission start --worktree` creates a member worktree via `createAgentWorktree()` (`commands/worktree.js`, shared with `worktree start`), links source `node_modules` only after git confirms the link is ignored, and uses the shared exclude file when needed. A bad manifest or link error warns and leaves the mission runnable. Mission state and receipts live inside the checkout. Regression: `test/mission-worktree-start.test.js`
- **Stop evidence:** full `mission stop` writes a `mission_stop` receipt (reason + worktree-vs-baseline, so `new_since_baseline_sample` shows what the abandoned mission left dirty) and sets `receipt_path` before pruning the baseline; `--pause` writes none. Regression: `test/mission-stop-receipt.test.js`
- **Cross-worktree rollup:** `mission status` merges sibling git-worktree missions via `listWorktreeRollupMissions()` (`commands/mission.js`, uses `listWorktrees()` from `commands/worktree.js`): read-only, deduped by id, annotated `worktree_root`/`worktree_branch` in JSON and a `worktree:` line in text; `--local` scopes to the current checkout; tick/complete still run inside the owning worktree. Regression: `test/mission-status-rollup.test.js`
- **Review-lane self-drain:** always-on `mission run` ticks call `runReviewLaneDrain()` (`commands/mission.js`, spawns `task review-lane-run --json`) and record the compact result as `tick.review_lane`; `--no-drain` records an explicit skip. - **Policy lesson mining (RSI):** `atris lesson mine [--json] [--dry-run]` (`mineLessons()` in `commands/lesson.js`) runs deterministic `lib/policy-lessons.js`. `mineProofPolicy()` separates the human gate from agent review, mines evidence patterns, writes `.atris/state/policy_lessons.json`, and refreshes `policy-<id>` lines in `atris/lessons.md` through `syncLessonsMd()` at `lib/policy-lessons.js:364`.
