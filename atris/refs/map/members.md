## Feature: Member Goal Loop (`atris member`)

**Purpose:** Give each team member a local identity contract, structured goals, inspectable progress, and a proof-scored review loop before Obelisk or cloud agents automate it.

- **Entry point:** `commands/member.js` (`memberCommand` dispatch)
- **Identity:** `atris/team/<member>/MEMBER.md`
- **Goal state:** `atris/team/<member>/goals.json` (`atris.member_goals.v1`)
- **Human readout:** `atris/team/<member>/goals.md`
- **Learning log:** `atris/team/<member>/logs/YYYY-MM-DD.md`
- **Install:** `atris member install <slug>` writes only missing MEMBER bundle files into `atris/team/<slug>/` and never overwrites; a complete folder prints `MEMBER already installed for <slug>`. `atris member install <slug> --update` atomically refreshes only packaged skill files and reports each changed path, or `MEMBER <slug> already up to date`.
- **Loop:** `atris member goal` -> `atris member tick` -> `atris member status` -> `atris member review --accept|--discard --proof ... --value 1..5`
- **Member run:** `commands/member.js` creates a mission from text or a useful-work choice, then drives it with the same budget and caller flags used for an existing mission. A check from `--verify` or member frontmatter is saved on the mission; unchecked runs use the mission's default check unless the caller passes `--no-verify`. Human output prints the checkout and dependency link before work starts; JSON reports `started` and `ok` from work actually run. `--detach` and `--dry-run` can succeed without a work step. `--mission <id>` resumes an existing mission. From a plain terminal a mission whose runner waits on a caller session (codex_goal) runs on the roster engine instead (`--engine auto`, `runner_swap` in JSON); a real codex caller (`CODEX_THREAD_ID`, native goal flags, or `ATRIS_CALLER_RUNTIME=codex`, see `lib/default-runner.js`) keeps the native goal and gets `waiting_on: native_goal_start`. JSON carries `work_step` (engine, model, duration, receipt) and, when the protected-surface guard pauses, `needs_review` with a one-line `ask` and `next_command`. `member wake` runs one bounded `member run` after deciding, from a plain terminal with a roster engine; `--plan` only decides. `bin/atris.js` forwards `process.exitCode` for `member run` only; other member subcommands retain a zero exit after returning.
