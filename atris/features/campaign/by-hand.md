# Running the first campaign by hand

Pain points from running "Campaign ships across Atris" before the store and CLI verbs existed (build.md Phase 0.5). Each one changed the schema or the build.

1. **Five folds would drift.** The first plan had every surface fold events. Screens only show state, so they now decode the view instead, and only the CLI and backend fold. The bet changed to match: a screen that computes campaign state is the failure.
2. **The contract was loose in 22 places.** The golden files were written by a member who never saw the fold code, and it logged 22 ambiguities (`test/fixtures/campaign/AMBIGUITIES.md`). One caught a real disagreement on the first run: the estimate on a mission skipped cents rounding. All 22 are now settled in the README.
3. **The spec's event list could not express two of its own actions.** `add_budget` and `veto` had no event. `budget_added` and `mission_vetoed` were added to the schema.
4. **Pin the golden files before sending anyone out.** Two screen members finished before `MANIFEST.json` existed, so the judge could not grade them until it was written. Next campaign: pin first, then dispatch.
5. **Decide needed state the view did not show.** "Run the judge when a mission ended after the last judge run" depended on hidden fold order. The view now carries `judge_due`, so every surface decides from the same fields.
6. **Cost is only known for Claude runs.** "Every mission reports its cost" holds for Claude today; Codex, Cursor, and the rest report tokens only, so their missions would spend without being counted. A price table, or a per-engine cost field in the roster run record, is needed before a campaign runs on them.
7. **Strict screens break on new words.** Terrace and desktop reject an unknown state value, so adding a state later needs every screen updated first. Fine for now; a future schema change should ship screens before computers.
8. **The judge must say what it did not check.** A partial run said "every surface agrees" when only two were checked. It now names the surfaces it skipped.
9. **Two languages disagree in the corners a review finds.** A cold review found that a timestamp without a zone folded differently by machine timezone, and that sorting at millisecond precision could flip two events a microsecond apart, which Python would order differently. The contract now requires a zone on every timestamp and compares instants at full precision. Golden files alone did not catch either; an adversarial reviewer did.
10. **A judge must not show the answers.** Runners used to receive the golden files with the expected results inside, so a runner could echo them and pass. The judge now hands runners inputs only.
11. **The campaign cannot see what it spent.** Its first nine missions ran as Claude Code subagents, which report tokens, not dollars, so the campaign shows $0 spent of $500. A mission cannot end honestly until it has a cost. The missions stay running until their PRs merge, and the cost reading has to exist by then: a price per model, or a dollar figure from each run.
12. **The campaign drove its own next move.** Once the work lived in the store as events, `decide` picked Phase 2 as the next mission on its own, because the judge had run and nothing waited on a person.
13. **Decide plans one mission at a time.** With nine missions running, `decide` answered "wait: missions running", so a campaign with a team working in parallel could not plan its next mission while others ran. Seats proposing their own missions (Phase 6) has to lift this, with a cap on missions at once.
14. **Fast campaigns found the cost hole in one round.** Three sandbox campaigns, each with one mission run by a headless Claude engine, all finished, but every mission ended at $0.00: a mission on a named runner never writes a roster run line, so the cost lookup found nothing, even though each tick's receipt said what it cost. Each tick now writes its own cost into the campaign as a step, and the mission's end adds them up.
15. **The judge's summary needs a telling line.** A test runner's output can end on a lone brace, which became the campaign's answer. The summary is now the last line that says something.
16. **Keep or revert on train fit only.** A teammate's Right Rooms campaign predicts which events Keshav picks, judged blind on held-out nights (38% to 88% picked right once it learned rules). Its gate keeps or reverts learned rules by training fit only, so the held-out set never steers what survives; otherwise the held-out score quietly becomes training data.
17. **A standing judge says healthy versus baseline, not better than last round.** With eight held-out cases the score moves by one case each round, so "beat the previous round" fails at random. Report the reading against a fixed baseline, and print the numbers on the judge's last line ("pass: backtest brier 0.111, top1 0.75 (baseline brier 0.181)").
18. **Money needs a ledger, not a timeline.** The first charging design capped each charge by where its event fell in time; backdated or late events each started from an unspent budget and charged three times the cap. The cap now comes from what the ledger has charged, under a lock.
19. **A campaign's work is not done until it is a pull request.** `cmp-budget-optional` passed its judge, but its best work (start from one sentence, a typed yes, `--run`) sat on a branch with no pull request for a day. Meanwhile master grew a second judge drafter, `campaign new`, so the two conflicted and the branch's pull requests were closed as superseded. It landed only when it was folded into `campaign new` (#1345). A kept mission should end in an open pull request, and the planner should check open branches before it proposes work that may already exist.
20. **A mission logged by hand stays running until someone ends it.** Two missions recorded by hand on `cmp-campaigns-live` were never ended, so the finished campaign listed two missions running. Their pull requests had merged, but cleanup only sees missions that have a mission record. End a hand-logged mission when its pull request merges: `atris campaign event <id> mission_ended --data '{"mission_id":"<m>","outcome":"kept","cost_usd":0}'`.
21. **A busy machine fails the release check, not the code.** The release check runs the whole test suite locally, and at a load average near 100 three tests killed their child process at 15 seconds. CI passed. The time limits now match how long a mission is allowed to run (#1314).
22. **A number in the objective became the mission's clock.** The suite-speed campaign's first mission read "Split test/commands.test.js (437 tests, 475s)". The mission parser takes times from the ask, so it gave the mission 475 seconds, and the mission was killed after 7.9 minutes of real work. Campaign missions now always start with an explicit time limit (`--mission-minutes`, 40 by default).
23. **One campaign, one driver.** While the suite-speed campaign ran from a clean clone, another agent started `campaign run` on it from the main checkout, three missions at once. Both loops planned against the same budget, and the second one's missions edited the main checkout, including a split the first loop had already landed. `campaign run`, `step`, and `propose` now take a lock beside the store and refuse while another live process holds it.
