# blocks spine, day 1 build brief

Written 2026-07-09 night. Grok-reviewed (verdict: build with changes, changes
taken). Roadmap: "The blocks plan". Serial spine, one engine at a time on
shared runtime files. Fable judges every landing; no engine grades its own work.

## slice 1: receipt block

- what: one receipt schema (extend atris.mission_receipt.v1, do not invent a
  second) with renderers: card, page section (markdown), email line, morning
  card row. Renderers live beside the existing render blocks (card/site/brief
  machinery) and reuse the theme system.
- exit: one recorded receipt object renders to all four surfaces in a test;
  morning card (atris now) shows a real receipt through the new renderer.
- verify: node --test on the new test file, then the full suite, CI run id cited.

## slice 2: verifier block

- what: typed verifier object {kind: command|adapter, spec, predicate,
  currency: developer|operator|civilian, freshness}. Missions accept it where
  shell strings go today; shell strings keep working (wrap as kind: command,
  currency: developer). Receipt block stamps the currency automatically.
- exit: the stranger-pays mission's verifier re-expressed as a typed object;
  one tick runs with it and the receipt carries the currency label.
- verify: mission tick receipt shows currency; full suite; CI run id cited.

## slice 3: intake block

- what: interview engine driven by question packs as data (json or markdown
  frontmatter). Port ONE existing surface to prove it: meet runs on a question
  pack with byte-identical behavior (same tests pass unchanged).
- exit: meet's interview is a pack file; theme-create and wish-drill get
  migration notes, not migrations (day 2).
- verify: test/meet.test.js unchanged and green; new intake tests; CI cited.

## slice 4: rainmaker-thin fixture pack (grok's keystone check)

- what: the smallest manifest that exercises slices 1-3: rainmaker-thin.md
  {name, niche, metric with floor, question pack, mission template, typed
  verifier, page copy}. A minimal compile step (even hand-wired) produces:
  an intake run, a mission with a typed verifier, and receipts rendering to a
  page section. This is a FIXTURE, not the compiler; the compile contract
  (block 7) is day 2+, designed against what this fixture teaches.
- exit: golden fixture test: manifest in, all three surfaces out, deterministic.
- verify: golden test green locally and in CI, run id cited.

## rules

- zero new runtime dependencies (Node built-ins only)
- serial: slice n+1 starts after slice n lands and is judged
- policy gate awareness now, implementation day 2: no block may send anything
  external; anything that would send is a stub behind a named gate
- lowercase output, no em dashes, plain english errors
- every landing: MAP.md entry, receipts with CI run id, post-merge judge pass
