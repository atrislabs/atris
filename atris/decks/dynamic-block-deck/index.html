scene 01 / origin

The brain becomes the product.

A pitch deck should not describe Atris from the outside. It should behave like Atris: memory, context, apps, code, images, and proof becoming one living surface.

This prototype treats each slide as a block-backed scene. It is closer to a live interface than a document.

scene 02 / contrast

Pixels are magic. Blocks are leverage.

Flipbook points at the future: interfaces streamed directly from models. Atris keeps the magic, but preserves the structure needed to edit, rerun, verify, and ship.

The winning surface is not static HTML versus generated pixels. It is generated experience with inspectable block lineage.

model -> pixelsfluid
interactive region visual state reshaped

Beautiful, immediate, shape-shifting. Harder to inspect, reuse, validate, or turn into durable software.

brain -> blocksshippable
app blockcustomer-facing workflow from APP.md
code blockexecutes, transforms, prototypes
image blockgenerates AtrisOS visual artifacts
deck blockcomposes the presentation surface
receipt blockproves prompts, files, checks, outputs

Still alive on screen, but each part can be edited, rerun, audited, shared, and composed into an app.

scene 03 / app manifest

APP.md says what the customer gets.

A manifest is not documentation. It is an instruction sheet for materializing software across web, Slack, voice, mobile, CLI, and deck surfaces.

Member says who. Skill says how. APP.md says what gets delivered. Blocks render it.
